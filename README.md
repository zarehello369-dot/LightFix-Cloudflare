# LightFix บน Cloudflare

แอปใหม่สำหรับแจ้งไฟถนนเสีย ติดตามงาน และจัดการงานของช่างกับผู้ดูแล ใช้ Cloudflare Workers สำหรับหน้าเว็บและ API, D1 สำหรับข้อมูล และ R2 สำหรับรูปภาพ หน้าเว็บสาธารณะใช้งานได้โดยไม่ต้องสมัครบัญชี

## ปรับหน้าจอสำหรับมือถือ (1 พฤศจิกายน 2026)

- หน้าแจ้งเหตุใช้ตัวเลือกอาการขนาดแตะง่าย ช่องกรอกและปุ่มส่งเต็มความกว้างบนมือถือ
- พื้นที่เจ้าหน้าที่และช่างใช้ตัวเลือกหน้าทำงานแบบเดียวบนมือถือและแท็บเล็ต ตารางแสดงเป็นรายการที่อ่านได้โดยไม่ต้องเลื่อนแนวนอน
- โลโก้เป็นสัญลักษณ์หลอดไฟเส้นสีเหลือง ส่วนชื่อ LightFix แสดงเป็นข้อความแยก
- การปรับครั้งนี้เปลี่ยนเฉพาะไฟล์หน้าเว็บ ระบบ API, D1, R2 และข้อมูลเดิมไม่ได้แก้

หน้าเว็บรุ่นนี้เผยแพร่บน Worker เดิมแล้วเมื่อ 1 พฤศจิกายน 2026 ตรวจหน้าแรกและ API สุขภาพบน URL จริงผ่าน

## สิ่งที่เตรียมไว้

- หน้าแจ้งเหตุที่เริ่มด้วยหมายเลขเสา พร้อมตรวจเลขเสาและแสดงสถานะการส่ง
- เลือกติดตามผ่านลิงก์โดยไม่ขอรับการติดต่อกลับได้ คำเตือนเสา/สายไฟอันตรายแสดงตามอาการ (ยังไม่มีเบอร์ฉุกเฉินของพื้นที่ที่ยืนยันแล้ว)
- รูปจากมือถือย่อเป็น JPEG สูงสุดด้านยาว 1600px ก่อนส่ง พร้อมภาพตัวอย่างและเอารูปออก รองรับ JPG/PNG/WebP ต้นฉบับไม่เกิน 25 MB
- คิวเรื่องแจ้งเริ่มจากงานที่ต้องทำ มีค้นหาและตัวกรอง และปิดปุ่มเริ่ม/มอบหมายเมื่อยังเลือกเรื่องไม่ถูกเงื่อนไข
- ช่องค้นหาคิวงานคง input เดิมขณะกรองรายการ เพื่อรักษาลำดับตัวอักษรและตำแหน่งเคอร์เซอร์ สถานะไม่พบงานแสดงคำค้น/สถานะและปุ่มล้างตัวกรอง
- ปุ่มรูปมีกรอบโฟกัสคีย์บอร์ด รูปประวัติแสดงเต็มสัดส่วนและเปิดต้นฉบับได้ ข้อความความเป็นส่วนตัวอยู่ข้างช่องแนบรูป และช่องอาการอื่นผูกกับข้อความผิดพลาดโดยตรง
- หน้าช่างเริ่มที่ “งานของฉัน” แสดงงานมอบหมายรอรับและงานที่กำลังซ่อม คิวเรื่องแจ้งรวมระดับเสา พร้อมจำนวนเรื่อง อาการ ผู้รับผิดชอบ และกำหนดเสร็จ เรื่องใหม่ของเสาที่กำลังซ่อมจะเข้าร่วมงานเดิม
- จำตัวกรองสถานะ/ค้นหาคิวงาน ค้นหาเสา และค้นหาบัญชีในเบราว์เซอร์แยกตามบัญชีและบทบาท ไม่บันทึกการเลือกเสาไว้ข้ามหน้า
- ตรวจ revision ของงานระดับเสาใน transaction ก่อนรับงาน มอบหมาย บันทึก ปิดงาน ยกเลิก และแก้ประวัติ หากข้อมูลเปลี่ยน จะปฏิเสธด้วย 409 ให้โหลดงานล่าสุด การมอบหมายใหม่ตัดสิทธิ์แก้งานของช่างเดิม
- หน้าเจ้าหน้าที่เพิ่มบัญชีได้พร้อมรหัสชั่วคราว ค้นหาบัญชี ลบบัญชีหรือเสาที่ไม่มีประวัติ และปิดใช้งานรายการที่มีประวัติเพื่อรักษาข้อมูลงานซ่อม
- หน้าติดตามรายงานและกระดานงานสาธารณะ โดยซ่อนข้อมูลติดต่อผู้แจ้ง
- เจ้าหน้าที่และช่างเข้าด้วยชื่อผู้ใช้/รหัสผ่าน LightFix โดยแยกสิทธิ์ตามบทบาท
- ฐานข้อมูล D1 จริงมีโครงสร้างครบแล้ว และนำเข้าเสา 50 ต้นกับชื่อผู้ใช้/บทบาท 3 บัญชีจาก CSV ที่ให้มา บัญชีที่นำเข้าถูกปิดไว้และไม่มีรหัสผ่านเดิม
- R2 bucket `lightfix-photos` สร้างแล้ว โดยแยกรูปที่ยังซ่อมไม่เสร็จใน `unrepaired/` และรูปของงานที่ซ่อมเสร็จใน `repaired/` เมื่อปิดงาน ระบบย้ายรูปก่อนซ่อมไปกลุ่มที่ซ่อมเสร็จพร้อมบันทึกรูปหลังซ่อม
- Worker เผยแพร่แล้วที่ `https://lightfix.service-fix.workers.dev/` และตั้งค่า `RATE_SALT` แล้ว ตรวจหน้าเว็บ, API, เสา T0001 และการกันหน้าผู้ดูแลที่ยังไม่ล็อกอินบน URL จริงผ่าน
- บัญชี `admin` ตั้งรหัสผ่านใหม่และเข้าสู่หน้าจัดการงานบนเว็บจริงได้แล้ว รหัสผ่านไม่อยู่ในไฟล์ส่งมอบ
- บัญชี `technician` เปิดใช้งานและเข้าสู่หน้าทำงานของช่างบนเว็บจริงได้แล้ว เจ้าของบัญชีต้องเก็บรหัสเองและเปลี่ยนรหัสชั่วคราวหลังเข้าระบบ

## ก่อนเปิดใช้จริง

1. ให้เจ้าของบัญชี `technician` เปลี่ยนรหัสชั่วคราว หากยังไม่ได้เปลี่ยน
2. ทดสอบวงจรงานจริงครบทั้งแจ้งเหตุ ติดตาม มอบหมายงาน ซ่อมเสร็จ และการจัดเก็บรูปก่อนส่ง URL ให้ชุมชน

บัญชี Cloudflare เปลี่ยน `workers.dev` subdomain เป็น `service-fix.workers.dev` แล้ว เว็บรุ่นล่าสุดอยู่ที่ `https://lightfix.service-fix.workers.dev/` ยังไม่มีการซื้อโดเมน

## คำสั่งสำหรับผู้ดูแลระบบ

ชื่อรูปใหม่ใน R2 ใช้หมายเลขเสา: `unrepaired/T0001/<report-id>/unrepaired-T0001.jpg` เมื่อปิดงาน รูปก่อนซ่อมย้ายไป `repaired/T0001/<repair-round>/before/<report-id>/T0001.jpg` และรูปหลังซ่อมอยู่ที่ `repaired/T0001/<repair-round>/after/T0001.jpg` โฟลเดอร์รอบซ่อมแยกรูปเพื่อไม่ให้ทับประวัติ นามสกุลตรงกับชนิดข้อมูลจริง (รูปจากหน้าเว็บถูกย่อเป็น JPEG) รูปเก่าที่เก็บด้วยชื่อเดิมยังเปิดผ่านระบบได้ตามเดิม

ต้องมี Node.js 20 ขึ้นไปและสิทธิ์ Cloudflare ของบัญชีปลายทาง ใช้ PowerShell ในโฟลเดอร์นี้

```powershell
npm install
npx wrangler login
```

ฐานข้อมูล D1 ของบัญชีนี้มี ID `486ee41d-4771-41cc-b472-fd9fd290fe4d` ซึ่งบันทึกใน `wrangler.jsonc` แล้ว โครงสร้างและข้อมูลนำเข้าเสร็จแล้ว **ห้ามรัน migration เริ่มต้นหรือ import ซ้ำ** ในฐานข้อมูลนี้ หากแก้โค้ดในอนาคต ให้ติดตั้งรุ่นใหม่ด้วย

```powershell
npx wrangler deploy
```

ถ้าต้องย้ายไปฐานข้อมูลใหม่ในอนาคต ให้ใช้ `scripts/prepare-import.mjs` กับ CSV ต้นฉบับอีกครั้ง ไฟล์ SQL ที่สร้างมีข้อมูลเสาและชื่อผู้ใช้จริง ต้องเก็บในพื้นที่ส่วนตัว ห้ามแนบใน repository หรือส่งต่อเป็นไฟล์สาธารณะ เครื่องมือนำเข้าจะไม่อ่านคอลัมน์รหัสผ่านหรือ hash เดิม

บัญชี `admin` บนฐานข้อมูลนี้ตั้งรหัสผ่านแล้ว หากย้ายไปฐานข้อมูลใหม่ ผู้ดูแลต้องกำหนดรหัสผ่านใหม่ให้อย่างน้อยหนึ่งบัญชี: ตั้งตัวแปร `LIGHTFIX_BOOTSTRAP_PASSWORD` ในสภาพแวดล้อมส่วนตัวให้เป็นรหัสอย่างน้อย 12 ตัวอักษร แล้วรัน `node scripts/prepare-admin.mjs <username> <display-name>` โดยบันทึกผลลัพธ์ไปยังไฟล์ SQL ส่วนตัวและนำเข้าด้วย `wrangler d1 execute ... --remote --file ...` อย่าแสดงผล SQL หรือรหัสผ่านในแชต/ประวัติคำสั่ง ลบไฟล์หลังใช้

## ทดสอบในเครื่อง

พื้นที่ช่างเปิดที่งานกำลังทำ สลับไปงานรอรับได้จากแท็บพร้อมจำนวน แต่ละเสามีอาการ รูปก่อนซ่อม และคำสั่งงานในบัตรเดียวกัน เจ้าหน้าที่มอบหมายจากบัตรเสาโดยตรง ภาพรวมแสดงจำนวนเสาและจำนวนเรื่องแจ้งแยกกัน

ฟอร์มความคืบหน้าและปิดงานเก็บข้อความร่างแยกบัญชี/บทบาท/งานใน `sessionStorage` ไม่เกิน 24 ชั่วโมง และล้างเมื่อบันทึกสำเร็จหรือออกจากระบบ รูปที่เตรียมอยู่ในหน่วยความจำเท่านั้น ปิดแล้วเปิดฟอร์มใหม่ในหน้าเดิมยังดูได้ แต่รีโหลดหน้าต้องเลือกรูปอีกครั้ง หากข้อมูลเปลี่ยนระหว่างทำงาน ปุ่มโหลดข้อมูลล่าสุดจะรักษาฟอร์มเดิมและให้ตรวจข้อมูลใหม่ก่อนส่งซ้ำ

```powershell
npm install
npx wrangler d1 migrations apply lightfix-db --local
npm run dev
npm run check
```

การทดสอบในเครื่องใช้หน้า Login เดียวกับระบบจริง โดยบัญชีที่นำเข้าจะยังเข้าใช้ไม่ได้จนกว่าจะตั้งรหัสผ่านใหม่และเปิดบัญชี

## ข้อจำกัดที่ต้องตัดสินใจก่อนใช้งานชุมชน

- ข้อความเตือนสายไฟชำรุดในหน้าสาธารณะยังไม่มีเบอร์ติดต่อฉุกเฉินของพื้นที่ ต้องเพิ่มช่องทางที่หน่วยงานยืนยันก่อนประกาศใช้งาน
- แบบฟอร์มยอมให้ผู้แจ้งใส่เพียงชื่อ จึงอาจติดต่อกลับไม่ได้ในบางกรณี หากการติดต่อกลับจำเป็น ควรบังคับช่องทางที่ติดต่อได้
- การนำเข้ารอบนี้ไม่มีงานซ่อมเก่า ประวัติซ่อม รูปเก่า หรือรหัสผ่านเก่า ตามขอบเขตที่ตกลงกัน
